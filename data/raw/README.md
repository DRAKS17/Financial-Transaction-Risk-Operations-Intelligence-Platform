# Raw Data Inventory & Provenance Guide

## 1. Storage Integrity Policy
All datasets stored in `data/raw/` are **pristine and immutable**.
- Under no circumstances should raw files be manually modified, overwritten, or directly cleaned in-place.
- All downstream transformations, deduplication, imputation, and feature extraction must output exclusively to `data/processed/`.
- Cryptographic SHA-256 hashes are logged to verify data lineage and chain of custody.

---

## 2. Inventory of Raw Files

### A. `paysim.csv` (Primary Transaction Stream)
- **Source**: PaySim synthetic financial dataset (Lopez-Rojas et al., 2016).
- **Scale**: 6,362,620 transaction records, 11 columns, ~470.7 MB.
- **Grain**: 1 row = 1 individual financial transfer or payment event.
- **Temporal Span**: Steps 1 to 744 (representing 30 days of simulation; 1 step = 1 hour).
- **Licensing**: Creative Commons Attribution-ShareAlike 4.0 International (CC BY-SA 4.0).
- **Attribution**: E. A. Lopez-Rojas, A. Elmir, and S. Axelsson, "PaySim: A financial mobile money simulator for fraud detection", In The 28th European Modeling and Simulation Symposium-EMSS, 2016.

#### Field Specifications:
| Column | Raw Type | Description | Analytical Purpose |
|---|---|---|---|
| `step` | Integer | Maps a unit of time in the real world (1 step = 1 hour, 1 to 744). | Enables time-series analysis and strict temporal train/test splitting. |
| `type` | Text | Transaction category: `CASH_IN`, `CASH_OUT`, `DEBIT`, `PAYMENT`, `TRANSFER`. | Primary segmentation variable for risk profiling. |
| `amount` | Numeric (Float) | Transaction amount in local currency units. | Continuous transaction scale; critical for exposure calculations. |
| `nameOrig` | Text | Unique identifier of originating customer/account (`C` + 9 or 10 digits). | Source account frequency, velocity, and repeat behavior. |
| `oldbalanceOrg` | Numeric (Float) | Balance of origin account before the transaction. | Pre-transaction liquidity check and anomaly detection. |
| `newbalanceOrig` | Numeric (Float) | Balance of origin account after the transaction. | Balance consistency verification (`oldbalanceOrg - amount == newbalanceOrig`). |
| `nameDest` | Text | Unique identifier of recipient account (`C` for customer, `M` for merchant). | Counterparty risk, fan-in/fan-out network analysis. |
| `oldbalanceDest` | Numeric (Float) | Balance of destination account before the transaction. | Recipient pre-settlement balance. |
| `newbalanceDest` | Numeric (Float) | Balance of destination account after the transaction. | Balance consistency verification on counterparty side. |
| `isFraud` | Integer (0/1) | Ground-truth fraud label generated by simulation rules. | Primary supervised machine learning target. |
| `isFlaggedFraud` | Integer (0/1) | Heuristic rule flag (marks single transfers > 200,000 currency units). | Baseline heuristic rule for benchmarking ML models. |

### B. `investigation_cases.csv` (Unstructured Operational Logs)
- **Source**: Synthesized companion operational case log generated deterministically.
- **Scale**: 5,000 case investigation records.
- **Grain**: 1 row = 1 fraud investigation ticket.
- **Linkage**: Foreign key `linked_transaction_id` referencing the originating PaySim transaction row index.
- **Operational Purpose**: Evaluates case triage, SLA compliance, backlog aging, and unstructured text analytics.

#### Field Specifications:
| Column | Raw Type | Description | Operational Purpose |
|---|---|---|---|
| `case_id` | Text | Unique investigation identifier (e.g., `CASE-2026-000001`). | Primary key for operations fact table. |
| `linked_transaction_id` | Integer | Foreign key pointing to the evaluated transaction. | Relational integrity link to `fact_transactions`. |
| `tx_step` | Integer | Transaction step when alert was generated. | Synchronizes case creation with transaction chronology. |
| `tx_type` | Text | Transaction type associated with case. | Channel workload categorization. |
| `tx_amount` | Numeric (Float) | Transaction amount under review. | Exposure-weighted triage sorting. |
| `case_created_at` | Text (ISO 8601) | Timestamp of alert trigger and case generation. | Backlog calculation and queue arrival time. |
| `case_status` | Text | Status: `OPEN`, `UNDER_REVIEW`, `CLOSED_CONFIRMED_FRAUD`, `CLOSED_FALSE_POSITIVE`. | Workflow tracking and resolution rates. |
| `priority` | Text | `P1_CRITICAL`, `P2_HIGH`, `P3_STANDARD`. | Queue prioritization and SLA tiering. |
| `assigned_team` | Text | `Tier 1 Operations`, `Senior Fraud Risk`, `Special Investigations Unit (SIU)`. | Capacity allocation and investigator workload metrics. |
| `investigation_notes` | Text | Free-text notes recorded by investigators with realistic data quality defects. | Text normalization, tokenization, and NLP indicator extraction. |
| `closed_at` | Text (ISO 8601) | Timestamp when investigation was finalized (empty if open). | Turnaround time (TAT) and SLA breach calculation. |

## 3. Ground-Truth & Synthetic Data Disclaimers

> [!IMPORTANT]
> - All customer names, account numbers, amounts, and investigation notes are **synthetic** or simulated.
> - They **do not** represent actual private customer records from Paytm, Morgan Stanley, HSBC, or any financial institution.
> - The `isFraud` label represents the output of the multi-agent simulator behavioral rules and should be treated as an analytical benchmark rather than real criminal convictions.
